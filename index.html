CH.1

Anti Capture

Anti_Capture.exe

  1. DIE → PE64, MinGW, ไม่ pack
  2. Ghidra import → analyze → Filter หา custom_anti_analysis_check → เปิด
  3. อ่านโค้ด: เช็คไฟล์ npcap.sys 2 รอบติด — key จริงอยู่ path ที่แทบไม่ถึงตามธรรมชาติ
  4. ก่อน patch: ต้องมี Npcap ติดตั้งจริง (เปิด Wireshark ติดตั้งแล้ว หรือรัน sc query npcap ต้องเห็น RUNNING)
  5. คลิกบรรทัด if (pFVar1 == NULL) { return "4566..." } ใน Decompile → Listing เลื่อนไปจุดเดียวกัน จะเจอ:
CMP   qword ptr [RBP-0x10],0x0
SETNZ AL
TEST  AL,AL
JZ    <ที่อยู่ success>   ← ต้องเปลี่ยนเป็น JMP (ไม่มีเงื่อนไข)
  1. คลิกบรรทัด JZ → คลิกขวา → Patch Instruction → พิมพ์ JMP ตามด้วย address ปลายทางเดิม → Enter
  2. File → Export Program → save เป็น AntiCapture_patched.exe
  3. รันไฟล์ → เห็น Answer
Answer
Final Key (hex): 2b 2a 29 29 2a 2b 2c 2d 2c 2d 2c 2d 2c 2b 5e 55 54 4f

Anti Packing

Anti_Packing.exe

  1. DIE → Packed UPX 5.02
  2. cmd: copy Anti_Packing.exe Anti_Packing_unpacked.exe → upx -d Anti_Packing_unpacked.exe
  3. Ghidra import ไฟล์ที่ unpack แล้ว → analyze → Filter หา drop_encrypted_file → เปิด
  4. เลื่อนหาบล็อก if (local_38[15]=='O' && local_38[14]=='T' && local_38[13]=='U' && local_38[12]=='^')
  5. คลิกบรรทัดนั้นให้ Listing เลื่อนตาม จะเจอ 4 ชุดนี้ติดกัน:
CMP  AL,0x4f
JNZ  <ที่อยู่ fail>      ← ตัวที่ 1: เปลี่ยนเป็น NOP
...
CMP  AL,0x54
JNZ  <ที่อยู่ fail>      ← ตัวที่ 2: เปลี่ยนเป็น NOP
...
CMP  AL,0x55
JNZ  <ที่อยู่ fail>      ← ตัวที่ 3: เปลี่ยนเป็น NOP

JZ   <ที่อยู่ success>   ← ตัวที่ 4: เปลี่ยนเป็น JMP (ไม่มีเงื่อนไข)
  1. Patch ทั้ง 4 จุด (คลิกขวาแต่ละบรรทัด → Patch Instruction) → File → Export Program → save เป็น Anti_Packing_patched.exe
  2. รัน → เห็น Answer

CH.5

ClockCheck

ClockCheck.exe

  1. DIE → ไม่ pack
  2. Ghidra → Filter custom_anti_analysis_check — วนลูป 1,000,000 รอบวัดเวลา ถ้าเร็ว set byte ที่ 3 เป็น 0x57
  3. Filter extract_file_next — เช็คว่า 3 byte XOR 0x1F แล้ว decode ได้ "O+H"
  4. คำนวณ byte ต้นฉบับที่ต้องมี: 50 34 57 (P, 4, W) — ข้อนี้ ไม่ patch jump เพราะ timing check ทำงานถูกอยู่แล้ว ปัญหาคือ byte ตัวกลางฝังผิดค่าไว้ในไฟล์ตรง ๆ ต้องแก้ด้วย hex editor
ครั้งแรกที่ใช้ hex editor: ทำตาม sub-step ด้านล่างทีละอย่าง ไม่ต้องรู้จักโปรแกรมมาก่อนก็ทำได้
  1. ติดตั้ง HxD (โปรแกรม hex editor ฟรี) — เปิด PowerShell (as Administrator) แล้วรัน: 
    winget install -e --id MHNexus.HxD
    รอจนติดตั้งเสร็จ (ไม่มี output อะไรพิเศษ แค่ prompt กลับมา)
  2. เตรียมไฟล์สำเนา — ห้ามแก้ไฟล์ต้นฉบับ ก็อปไฟล์ก่อน: 
    copy ClockCheck.exe ClockCheck_patched.exe
  3. เปิดไฟล์ใน HxD — เปิดโปรแกรม HxD (หาจาก Start Menu พิมพ์ "HxD") → File → Open → เลือก ClockCheck_patched.exe
    จะเห็นหน้าจอแบ่ง 3 คอลัมน์: เลข offset (ซ้ายสุด), ตัวเลข hex เป็นคู่ ๆ (ตรงกลาง), ตัวอักษร ASCII (ขวาสุด) — ทั้งหมดคือเนื้อไฟล์แบบ raw byte
  4. ไปที่ตำแหน่งที่ต้องแก้ — กด Ctrl+G (เปิดกล่อง "Go to offset") พิมพ์ 3601 (ไม่ต้องใส่ 0x นำหน้า, HxD default เป็น hex อยู่แล้ว) → กด OK
    cursor จะกระโดดไปตำแหน่งนั้น มี byte ถูก highlight ไว้
  5. ตรวจว่าถูกตำแหน่ง — byte ที่ highlight ต้องเป็น 58 (ถ้าดูคอลัมน์ ASCII ด้านขวาจะเห็นตัวอักษร X ตรงกัน) ถ้าไม่ตรง แปลว่ากด Ctrl+G ผิดค่า ลองใหม่
  6. แก้ค่า — คลิกที่ byte 58 นั้น 1 ครั้งให้ cursor กระพริบอยู่ตรงนั้น แล้วพิมพ์ 34 ตรง ๆ เลย (พิมพ์ทับได้ทันที ไม่ต้องลบก่อน) — byte จะเปลี่ยนจาก 58 เป็น 34 ทันที และตัวอักษรฝั่ง ASCII จะเปลี่ยนจาก X เป็น 4
  7. บันทึกไฟล์ — กด Ctrl+S (หรือ File → Save) — เสร็จแล้ว
  8. double-click ClockCheck_patched.exe รัน → MessageBox "Congratulations!" ขึ้น → เปิด flag.txt ที่ถูกสร้างในโฟลเดอร์เดียวกัน
เช็คผลให้ชัวร์: เปิด flag.txt ต้องอ่านออกเป็นประโยคภาษาคน ถ้าเจอตัวอักษรมั่ว ๆ อ่านไม่ออก แปลว่า byte ที่แก้ยังผิด หรือ save ไม่สำเร็จ ให้กลับไปเช็คขั้นตอน 4-6 ใหม่
flag.txt
hack me at 127.0.0.1
